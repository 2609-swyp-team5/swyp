# 체크포인트 (작업 요약 → 히스토리 정리)

긴 작업을 여러 단계로 진행할 때, 각 단계가 끝날 때마다 아래 순서를 따른다.
목적은 다음 단계를 **대화 히스토리 없이 PROGRESS.md만 읽고도** 이어갈 수 있게 만드는 것이다.

## 1. 작업 결과 및 현재 상태 요약 정리

프로젝트 루트 `PROGRESS.md`의 "현재 상태" 맨 위에 항목 하나를 추가(또는 같은 작업 항목을 갱신)한다.
다음 내용을 빠짐없이 적는다.

- **완료한 단계**: 무엇을 바꿨는지(파일·클래스·마이그레이션 번호), 커밋 해시, push 여부, 브랜치
- **검증 결과**: 실행한 테스트와 통과 수(예: 전체 250/250 + spotlessCheck), 실행하지 못한 검증
- **결정 사항**: 이번 단계에서 스스로 정한 기본값이나 설계 선택, 사용자 확인이 필요한 것
- **남은 단계**: 사용자가 요청한 작업 목록 중 아직 안 한 것과 그 순서(원문 요청 문장도 인용)
- **재개 방법**: 다음 세션이 바로 시작할 수 있도록 체크아웃할 브랜치, 작업 트리 상태(미커밋 파일, 커밋하지 말아야 할 파일)

"다음 작업" 섹션에도 남은 단계를 우선순위 맨 앞에 반영한다.
문서가 500줄을 넘으면 CLAUDE.md의 문서 관리 규칙대로 오래된 항목을 압축한다.

## 2. 대화 히스토리 삭제

대화 히스토리는 Claude가 스스로 지울 수 없다(`/clear`, `/compact`는 사용자만 실행할 수 있는 CLI 명령).
그러므로 요약 저장을 마치면 작업을 멈추고 다음처럼 알린다.

> 체크포인트 저장 완료(PROGRESS.md). `/clear`로 히스토리를 지운 뒤 "이어서 진행해줘"라고 입력해 주세요.

사용자가 `/clear` 후 이어서 진행을 요청하면, CLAUDE.md 4단계 규칙대로 PROGRESS.md 전체를 먼저 읽고
"재개 방법"과 "남은 단계"에 따라 다음 단계를 진행한다.
