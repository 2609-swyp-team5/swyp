# 번개장터 시세 수집 API 참고

> 이 문서는 PROGRESS.md와 별도로 관리합니다. **시세 데이터 수집(크롤링) 작업을 할 때만** 참고하세요.
> 확인일자: 2026-09-18 (브라우저 Network 탭 캡처 + 실제 요청 테스트로 확인)

## 엔드포인트

```
GET https://api.bunjang.co.kr/api/search/v8/pw/product/specs/category
```

이름은 "specs/category"지만 실제로는 **카테고리별 상품 목록 자체**를 반환한다(specs는 응답에 포함된 UI 블록 구조의 policyKey 명명일 뿐).

### 파라미터

| 이름 | 필수 | 설명 |
|---|---|---|
| `categoryId` | O | 번개장터 자체 카테고리 ID (예: `310300200` = 여성의류>아우터>패딩). **우리 `categories` 테이블 코드 체계와 다름 — 매핑 테이블 필요** |
| `sort` | X | `latest`(최신순, 기본)/`popular`(인기순)/`price_asc`/`price_desc` |
| `cursor` | X | 다음 페이지 토큰. 최초 요청 시 생략, 이후 이전 응답의 `nextCursor` 값을 그대로 전달 |

`page`/`offset` 같은 파라미터는 무시됨 — **페이징은 `cursor`로만 동작** (실제 두 번 요청으로 다른 `pid` 목록이 나오는 것 확인함). 페이지당 60건 고정으로 보임.

### 인증/헤더

- 쿠키·인증 토큰 **불필요** (캡처된 curl에 있던 `_bgzt_lc_sid`/`x-bun-context` 없이도 200 응답 확인됨 — 세션 특정 값이라 재사용도 안 됨)
- 필요 헤더: `origin: https://m.bunjang.co.kr`, `referer: https://m.bunjang.co.kr/`, `user-agent`(브라우저처럼 보이는 값). `sec-fetch-site: same-site` 체크가 있어 보이므로 origin/referer는 유지 권장(제거 테스트는 안 해봄).
- **User-Agent에 Claude/Anthropic 관련 문자열 사용 금지** — 아래 robots.txt 참고. 자체 서비스 식별 UA(예: `JigeuminiPriceBot/1.0 (+연락처 or 서비스 URL)`) 사용할 것.

### 요청 예시 (검증됨, 쿠키/개인 세션값 제거)

```bash
curl -s -G 'https://api.bunjang.co.kr/api/search/v8/pw/product/specs/category' \
  --data-urlencode 'categoryId=310300200' \
  --data-urlencode 'sort=latest' \
  -H 'accept: application/json, text/plain, */*' \
  -H 'origin: https://m.bunjang.co.kr' \
  -H 'referer: https://m.bunjang.co.kr/' \
  -H 'user-agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/153.0.0.0 Safari/537.36'
```

다음 페이지는 위 응답의 `nextCursor` 값을 `--data-urlencode "cursor=<값>"`으로 추가.

### 응답 구조

```
data.searchSpec.uiBlockList[]  — 배열, id로 블록 구분
  - id: "pwCategoryHeader"
    .categoryHeaderResponse: { name, category1Name, category2Name, category3Name }  ← categoryId 검증용
  - id: "mainGridSortCount"
    .searchCountResponse.totalCount  ← 카테고리 전체 매물 수
  - id: "mainGrid"
    .searchResponse:
      .data[]        ← 실제 상품 목록 (아래 필드 표)
      .cursor        ← 이번 페이지 조회에 쓰인 cursor
      .nextCursor    ← 다음 페이지 요청 시 전달할 값
      .totalCount
```

### 상품 아이템 필드 (`searchResponse.data[]` 각 원소)

| 필드 | 설명 |
|---|---|
| `pid` | 게시글 ID (Redis 중복 체크 키로 사용) |
| `name` | 상품명(제목) |
| `price` | 가격(원) |
| `status` | 판매상태 (`SELLING` 등 — 값 종류 전수 확인은 안 함) |
| `productImage` | 이미지 URL, `{res}` 플레이스홀더 포함(해상도 지정용으로 추정) |
| `shop.uid` | 판매자 ID |
| `favoriteCount` / `buntalkCount` | 찜/대화 수 |
| `updatedAt` | ISO8601, 최근 갱신 시각 |
| `ad` | **광고 여부** — `true`인 항목은 검색 연관도/입찰가로 노출 순서가 결정되어 가격 왜곡 가능성 있음. **시세 집계 시 `ad:true` 항목 제외 권장** |
| `care`, `video`, `type` | 용도 미확인 |

## robots.txt 확인 결과 (`m.bunjang.co.kr`, 2026-09-18)

- `User-agent: *` (일반 봇): `/login`, `/apps`, `/talk2`만 Disallow, **나머지는 Allow** — 상품 목록 경로 자체는 일반 크롤러에 허용된 상태.
- **`ClaudeBot`, `anthropic-ai`, `Claude-Web`: 사이트 전체(`/`) Disallow.**
- `Claude-SearchBot`, `Claude-User`: 일반 봇과 동일한 제한(`/login`,`/apps`,`/talk2`)만 적용.
- `GPTBot`, `Google-Extended`, `CCBot`, `Bytespider` 등 다수 AI 크롤러도 전체 Disallow.

**시사점**: 자체 서비스 크롤러는 Claude/Anthropic 관련 User-Agent를 쓰면 안 됨. 크롤링 자체의 이용약관 적법성 여부는 이 문서 확인 범위 밖이며(사업적/법적 판단 필요), 기존 설계 결정("원시 매물 데이터 DB 미저장")으로 리스크를 일부 완화 중인 상태. **사용자 확인 후 리스크를 감수하고 진행하기로 결정(2026-09-18)**.

**실제 구현에 사용한 User-Agent**: `JigeuminiPriceBot/1.0` (브라우저 위장 없이 정직하게 식별, `BunjangClientConfig` 참고). 이 UA로 실제 요청 시 200 응답 확인함(차단 없음).

## 카테고리 전체 트리 조회 API (2026-09-18 추가 발견)

```
GET https://api.bunjang.co.kr/api/mdms/v1/categories
```

인증 불필요, 헤더는 위와 동일. 번개장터 카테고리 **전체 트리**(대/중/소분류, 총 803개 노드)를
한 번에 반환한다. 각 노드: `id`(categoryId), `name`, `displayName`, `numChild`, 하위
`categories`(재귀). 우리 `categories` 테이블과의 매핑을 자동화하는 데 사용.

**중요**: 상위(비-리프) `categoryId`로 목록 API(`specs/category`)를 호출해도 하위 카테고리
매물이 전부 롤업되어 반환됨을 확인함(예: 중분류 "아우터"=`310300`으로 조회 시 그 밑 "패딩"/
"점퍼" 등 전체 합산 결과 반환). 즉 우리 카테고리가 번개장터보다 얕은 깊이에서 끝나도(예: 우리는
"여성 아우터"가 리프, 번개장터는 그 밑에 "패딩"/"점퍼" 등이 더 있음) 상위 categoryId로 매핑하면
정상 동작한다.

## 카테고리 매핑 진행 상황 (2026-09-18)

**대분류 25개는 검증 완료**, `application.yaml`의 `crawl.bunjang.category-mapping`에 반영함
(이름이 사소한 표기 차이만 빼고 1:1 대응돼 수작업 확인이 쉬웠음: 주얼리↔쥬얼리, 패션잡화↔패션
액세서리 정도).

**중분류/소분류 157개는 이름 자동 매칭을 시도했으나 검증 없이 설정에 넣지 않음** — 정확히
정규화된 이름이 일치하는 53건도 있지만, 이름을 `/`로 쪼개 부분 매칭하는 fallback 로직에서
**오매칭 사례를 실제로 확인함**(예: 우리 중분류 "TV/영상가전"이 번개장터의 더 좁은 리프
카테고리 "TV"로 잘못 매칭됨 — 실제로는 "TV/영상가전"에 해당하는 번개장터 상위 노드로 매핑해야
하는데, 리프 "TV"로 좁혀져 "프로젝터"/"셋톱박스" 매물이 통계에서 빠지게 됨). 아래 표는 **초안**이며
사용 전 하나씩 확인이 필요하다.
